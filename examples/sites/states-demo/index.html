OpenQuick UI states demo

This example shows accessible loading, empty, error, permission denied, rate limited, and offline states for static sites that call the same-origin OpenQuick SDK. Every API call is wrapped so a failed host capability becomes visible UI instead of an unhandled console error.

Implementation notes

  • Use role="status" for passive updates and role="alert" for actionable failures.
  • Read error.code, error.status, and quota fields from OpenQuickError.
  • Keep fallbacks useful when DB, AI, uploads, realtime, or identity are disabled by host config.
